# Running the SSAS tests in this repository's CI

[ssas.md](ssas.md) is QIS's record of how a Tabular server was found, what it needed and what the first runs showed; it stays as it was imported. This is how the suite runs it now.

- **What runs where.** The SSAS source of the sample catalog (`ssas_finance`) is emitted as DAX. On the Linux jobs and on a developer machine without a server it runs on the DuckDB stand-in. With `DBDATA_TEST_SSAS` set (the connection string of an instance without a catalog, such as `Data Source=localhost:2383`), `EngineConformanceTests` deploys `conformance/ssas/model.tmsl.json` of `DbDataKit.Semantic.Tests` as database `qis_budget` and runs every fixture, in the three subtotal modes, with `SsasExecutor` (`DbDataKit.Semantic.Ssas`) for that source. `DBDATA_REQUIRE_SSAS=true` fails the tests instead of skipping them.
- **The job.** `semantic-ssas` in `.github/workflows/dbdatakit-ci.yml`. It runs on a pull request only when the pull request changes `Emit/DaxEmitter.cs`, `conformance/ssas/` (the model) or `DbDataKit.Semantic.Ssas` (job `ssas-changes` decides; owner's decision 2026-10-27), and by hand (Actions, "DbDataKit CI", Run workflow, `ssas` on; `ssas_probe` runs only `SsasProbe`, which writes what a set of DAX shapes returned to `ssas-probe.txt`). It installs Analysis Services Tabular with Chocolatey on `windows-2022` (about 3 minutes), reads the instance's port from `msmdsrv.port.txt`, runs the suite and groups failures by cause from the TRX file. Run it after a change to the DAX emitter, the catalog's DAX bindings, the model or `SsasExecutor`. QIS's last runs of the same steps passed all 503 tests (run 12, 2026-10-27).
- **Left out on purpose:** the `bootstrapper` install method of QIS's workflow (it hung in three runs; Chocolatey is the method that works). The self-hosted VM in ssas.md is still the fallback if hosted installs stop working.
- **Always on, everywhere:** `SsasModelTests` keeps the model from drifting from the seed data and from the catalog's DAX names.
- **Decided:** no nightly run. **Not decided here:** the Windows job of J16 that hosts the executor in Proxy.
