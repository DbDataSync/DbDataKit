# Editors: where a person authors and publishes what the suite stores

The owner's order (2026-11-08): **every feature that can be built and published has an editor screen in the console, the Build or Sync workspace, or the Gateway's screens.** This page lists each thing a person can author, publish or configure by file or command, where its editor is today, how complete it is, and which slice closes the gap. [ui-coverage.md](ui-coverage.md) is the other half: it lists screens and the actions on each object; this page starts from the things (every stored format of `docs/formats.json`, the `publish`, `save` and `set` verbs, the management routes, the plans) and asks whether a screen edits them.

Read as of 2026-11-08 from the code of `DbDataKit/web/*`, `DbDataGateway/src/DbDataGateway.Server/Management`, `DbDataBuild/src/DbDataBuild.Cli/Server`, `DbDataStore/src/DbDataStore.Server`, `DbDataKit/src/DbDataKit.Runner.Api` and the plans' status lines, not from plan prose alone. The screens are shown by the console (`DbDataKit/web/console`) at `/servers/<server>/...`; "Gateway" below is the Gateway's own screens (`DbDataKit/web/gateway`), "Build" and "Sync" are the product screens of `DbDataKit/web/build` and `DbDataKit/web/sync`.

**States.** `full`: a person can create, edit, check and publish (or save) and remove it, from a screen. `partial`: some of that, the gap column says what is missing. `view-only`: the screen shows it and changes nothing. `none`: no screen. `planned`: not built, a plan owns it. A state other than `full` names the slice that closes it in the last column (`UEnn` of [plan 33](plans/33-ui-editors.md), or the slice of another plan that owns the screen), or carries its reason in parentheses: `none (reason)`. A "route" below is a management API route; "exists" was checked in the server's code.

**The rule.** A stored format registered in `docs/formats.json` must have a row here with a state. `scripts/check_ui_editors.py` fails, naming the format, when one has none, when a row names a format that is not registered, a `UEnn` that is not in plan 33, a screen file that does not exist, or a `Counts:` line that is wrong. A format that needs no editor gets the row and `none (reason)`.

Counts: full 21, partial 9, view-only 1, none 8, planned 7.

The table is sorted by what blocks "ready to test soon" (apps, dashboards, reports, quality, runner scheduling), then the other gaps, then the planned, then what is complete. The Format column is the id in `docs/formats.json`; `-` means the thing is not in the registry (see "Not in the registry" below).

## Not in the registry

`docs/formats.json` lists eleven formats. These stored things have no entry, so the check cannot see them; each deserves one when its slice touches the format (plan 24a UC02): the app manifest `app.yaml` and the portal and home-view files, `check/1` (`DbDataKit.Quality`, "new and open" in plan 23a FQ01), `access/1` (GP01, not built), navigation sets and app instances (definitions kept by `DbDataKit.Apps.Instances`), the Gateway's `server.yaml` and `auth.yaml`, Sync and Build connection files other than `connection/N`, Build's plan files (`plan.schema.json`) and the runner's other kinds. Until they are registered their rows say `-` in the Format column.

## How the screens are tested

A console screen has a Playwright story in `DbDataConsole/tests/DbDataConsole.Web.Tests/tests`, a Sync screen in `DbDataSync/tests/DbDataSync.Web.Tests/tests`. Whether every screen above has one is not audited here (the stories named in the table were found by file name, not run); the one known to be missing is the Store entity editor (UE18).
