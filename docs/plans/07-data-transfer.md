# Plan 07: Data Transfer, Staging and Loading (`DbDataKit.Transfer`), what is left

Status: **in progress, low priority** (audited 2026-11-09 against the code). What is built is in `Shared/src/DbDataKit.Transfer*/README.md`: value conversion, staging policy, strategy SQL builders and the capability matrix, the write gate and its rules (the section "Rules both products keep"), the conformance suite (`DbDataKit.Transfer.Conformance`, Build's strategies on SQL Server and PostgreSQL, a DuckDB reference), the SQL Server and PostgreSQL bulk writers, and the strategy semantics of Sync and Build. This plan holds only unbuilt work; there is no scheduled driver for any row except TR01 and TR07, and the rest wait for the trigger named in their row.

Audit (what the owner's list said, against the code): **Arrow-first and Parquet staging** is not built (`DbDataKit.Transfer.Abstractions` has `AsArrow()` as an adapter on `DataBatch`; `Shared/benchmarks/DbDataKit.Transfer.Benchmarks` compares reader and DataTable feeding without a database, and says the live half is missing; no Parquet or Arrow file provider exists). **`ITransferVerifier`** is an interface only; the implementations are Sync's `DbDataSync.Verification` and `VerificationComparison`/`VerificationStatement` (in `DbDataSync.Drivers.Generic`) and Build's `connection compare` and `check`. **Segmenting** (`ISegmenter`) lives in Sync only (`DbDataSync.Drivers.*` and the segmenting cards in `web/sync`), no shared package exists and Build has no parallel copy yet. **MySQL and Oracle writers** exist only as Sync's drivers (`DbDataSync.Drivers.MySql`, `.Oracle`); `DbDataKit.Transfer.SqlServer` and `.Postgres` are the only shared ones, and SCD2 and Snapshot are not shared strategies. **Sync does not use `WriteGate`** (`git grep WriteGate DbDataSync` finds nothing); Build does (its `MutationGate` is the front). The Windows ACL on the statement log is not set (the log inherits the directory ACL, said in the README).

Nothing here stores a new file format: no row changes a format of `docs/formats.json`, and none builds something a person authors, so no row needs an editor row in `docs/ui-editors.md` (these are libraries behind the products' screens; the exemption is recorded here, per that page's rule).

## Decisions

1. **Reader-shaped interchange stays the default; Arrow-first is a measured option** (TR02), the direction the plan always held. Default taken (owner delegated, 2026-11-09).
2. **MySQL, Oracle, SCD2, Snapshot and segmenting move to the shared packages only when a second product needs them**, as before; they are parked, not forgotten. Default taken (owner delegated, 2026-11-09).
3. **Sync adopting the gate (TR04) comes before any other move,** because the other moves (TR05, TR07) must go through the gate to be shared, **and it comes after Sync is operational on the runner** (plan 28c): the gate is not threaded through the engine twice, once in the old worker and again in the runner's drain. Default taken (owner delegated, 2026-11-09).
