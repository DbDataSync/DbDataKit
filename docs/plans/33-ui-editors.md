# Plan 33: an editor screen for everything a person can build and publish

Status: **proposed** (2026-11-08). The owner's order of 2026-11-08: *make sure that any features that can be built and published have a UI editor screen in the workspace or console somewhere.* The audit that answers "where is it today" is [docs/ui-editors.md](../ui-editors.md) (one row per thing, its state and the slice that closes the gap); this plan is the slices for the rows that no other plan owns. It adds no feature: every slice is a screen over something that already exists (a route, a verb, a stored format) or that a built plan defined.

A slice is one commit on the batch's branch, "done" is the test in the last column but one, and the slice's status goes in its row in the same commit (the shape of [28a](28a-runner-slices.md) and [29a](29a-state-slices.md)). A slice also changes its row in `docs/ui-editors.md` (and the matrix in `docs/ui-coverage.md`) in the same commit; `scripts/check_ui_editors.py` fails when a registered format has no row or a row names a slice that is not here.

## What a screen slice delivers

1. The screen in the product's own web module (`DbDataKit/web/<product>`), shown by the console at `/servers/<server>/...`: **the console's per-server screens** (Runner, Store, Gateway) or the **Build and Sync workspaces**. No product has a web app of its own.
2. Create or edit, **check before saving** (the server's own diagnostics, never a second validator that can disagree), save or publish, and remove where the rules allow; a refusal is shown in the server's words. Writes quote the version they read (a stale one is refused with the current).
3. Roles as the server decides them (Viewer, Operator, Author, Approver, Admin); the screen offers what the token allows and the server checks again.
4. Test ids on every control (`<area>-<thing>-<action>`), as the existing screens have them.
5. **Done when** a component test (vitest, the screen without its calls, as `PublishView` is tested) and **one Playwright story** (console: `DbDataConsole/tests/DbDataConsole.Web.Tests/tests`; Sync: `DbDataSync/tests/DbDataSync.Web.Tests/tests`) pass: create or change the thing in the screen, see the server accept it, and see the effect in the screen that reads it. The story contacts no host but its own servers (the pattern of `views-editor.spec.ts`).

## Order

By value for testing soon, apps first, then the editors of the runner's scheduling, then the rest. The slices other plans own are listed after the table with the order they should be pulled in; they are not repeated as rows.
