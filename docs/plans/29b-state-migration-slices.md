# Plan 29b: what is left of moving state between engines

Status: **in progress, what is left** (audited 2026-11-09 and again 2026-11-11 against the code and the tests). Moving state between engines (offline, with a restart), the snapshot format, the verifier, the shared `state` verbs in every product's command line (`show`, `test`, `init`, `export`, `import`, `verify`, `move`, `grants`), the one `state:` section every product reads and its writer, the topology presets, the management API and maintenance mode, the console's state connections and Move wizard, the engine support matrix (SQL Server 2022 and 2025, PostgreSQL 16 and 17, CI on both) and mixed-version groups are built and tested. Their slices X01 to X04, C01 to C04, C06 and U01 to U03 are deleted from this plan (U03, scheduled snapshots as backups, is the console's `state-backup` task) (C04, the encrypted columns a move decrypts, and C06, the server's own checks of the target and a SQLite file on the server as a target, were built on 2026-11-11: `DbDataKit.State.Cli/README.md` and `DbDataKit.State.Api/README.md`); the design is documentation beside the code: **`Shared/src/DbDataKit.State/README.md`** ("Moving state between engines": the snapshot, import into an empty target, verification, secrets, the offline rule), `DbDataKit.State.Cli/README.md` (the verbs and exit codes), `DbDataKit.State.Api/README.md` (the endpoints and maintenance mode), `DbDataKit.State.Engines/README.md` (the settings order, the support matrix, features per module, rolling upgrades). The decisions of the owner (2026-11-07) that stay true: a restart is fine and moving is offline; the snapshot is gzipped JSON lines (engine-neutral; native backups stay the administrator's tool); the old database is left behind and the tool prints how to go back; the console's own state is moved from the command line while other servers' moves can start from the console.

Slices follow the shape of [29a](29a-state-slices.md): one slice, one pull request, "done" is the test in the last column, the row is deleted when it is done. A row that keeps an id of the old plan is what remains of that slice.
