# Plan 28a: what is left of the runner

Status: **in progress, what is left** (audited 2026-11-09 against the code and the tests; the built slices R01 to R20 are deleted from this plan, and what is still true of them is documentation beside the code). The runner exists: a package model (`package/1`), a protocol with both ends, the typed kit and its simulator, the executor with limits, retries, triggers, labels and posture choices, the scheduler loop, groups, publishing and staging with activation that waits for runs in flight, the console's screens and the embedded runner. This plan holds only the open work; the engines moving onto the runner (Sync and Build) are [plan 28c](28c-engines-on-runner.md).

Slices follow the shape of the suite slices (`CLAUDE.md`, "Making changes"): one slice, one branch `suite/r<nn>-<short-name>`, one pull request, "done" is the test in the last column, and the slice's row is deleted in the commit that finishes it. A row that keeps an id of the old plan (R07, R13, R16, R19, R20) is what remains of that slice.

## Risks

- **Linux limits:** cgroup v2 may be unavailable to the CI container; the watchdog is the tested path and cgroup is tested where it can be (R07).
- **Windows:** the named-pipe host, the job object and the cache's hard-link views (`CreateHardLinkW`, deleting a read-only link, a long path) are untested in CI until the Windows job of R27 runs.
- **Manifest drift:** the manifest, the progress declaration and the kit's generated declaration must agree; `ManifestGenerator` gives the .NET side one model and staging compares the two.
- **The engines meet the runner in 28c:** each of Sync and Build is where their assumptions meet the runner's; they must not start before the runner runs real packages (it does: the proof tasks of E01 and E03 run on it).
