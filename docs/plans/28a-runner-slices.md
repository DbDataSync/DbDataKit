# Plan 28a: what is left of the runner

Status: **in progress, what is left** (audited 2026-11-09 against the code and the tests, re-audited 2026-11-11: every row below was still open as written then; R19 and R25 are built since (2026-11-12, the operator API and the runner screens: `DbDataRunner/README.md`, "What an operator answers"); the built slices R01 to R20 are deleted from this plan, and what is still true of them is documentation beside the code). The runner exists: a package model (`package/1`), a protocol with both ends, the typed kit and its simulator, the executor with limits, retries, triggers, labels and posture choices, the scheduler loop, groups, publishing and staging with activation that waits for runs in flight, the console's screens and the embedded runner. This plan holds only the open work; the engines moving onto the runner (Sync and Build) are [plan 28c](28c-engines-on-runner.md).

## Risks

- **Linux limits:** cgroup v2 may be unavailable to the CI container; the watchdog is the tested path and cgroup is tested where it can be (R07).
- **Windows:** the named-pipe host, the job object and the cache's hard-link views (`CreateHardLinkW`, deleting a read-only link, a long path) are untested in CI until the Windows job of R27 runs.
- **Manifest drift:** the manifest, the progress declaration and the kit's generated declaration must agree; `ManifestGenerator` gives the .NET side one model and staging compares the two.
- **The engines meet the runner in 28c:** each of Sync and Build is where their assumptions meet the runner's; they must not start before the runner runs real packages (it does: the proof tasks of E01 and E03 run on it).
