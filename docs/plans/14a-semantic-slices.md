# Plan 14a: the semantic layer, what is built and what is left, in slices

Status: **in progress** (proposed 2026-11-09; audited again 2026-11-11: SL01, SL05, SL12 to SL18, SL21, SL23 and SL24 are built, the other SL01 to SL31 rows are not; SL40 to SL55 are deferred and unscheduled; section 1 below is the audit of 2026-11-09 and was not rewritten). [Plan 14](14-semantic-layer.md) says what is left of the semantic layer; this plan audits it against the code (section 1, every item with the file or test that shows it), slices what no slice owned (sections 6 and 7) and keeps the owner's deferral of 2026-11-09 visible: **MDX and XMLA for Excel PivotTables and every extra protocol (Postgres wire, Quack) are low priority, written here as slices that are not scheduled, and nothing else depends on them** (section 7). The slices that already exist stay where they are (the J rows, once plan 19's, now only in section 2; plan 20, plan 22a, 23a, 24a); section 2 maps each so nothing is sliced twice. The shape follows [28a](28a-runner-slices.md) and [23a](23a-first-run-and-quality-slices.md): one slice, one commit on the batch branch, `SLnn: ...`, its status in its row in the same commit; "done" is the test in the last column but one.

Read on `origin/main` at `77692cdb` (2026-11-09) from the code, the tests and the plans' own status lines, not from plan prose alone. The product is the **Gateway** (it was the Proxy until batch 17); plan 14 still says Proxy in places.

## 10. Risks

- **The explorer's run path is the views module's preview** (D18): it was built for widgets, so a query that is not a widget query (explain, describe, members for a parameter) needs small additions there or J28; the risk is two paths to run a request. SL14 keeps the call behind one client function so J28 can replace it.
- **A decimal answer changes a client-visible type** (SL09): clients that read the number as `double` now see `decimal128`. The slice is a clean break the schema and the release notes announce (D33), never a silent one; `docs/semantic/open-questions.md` already lists the numeric type decisions of the Arrow path.
- **The registry can block a working product** (SL02 to SL04): a wrong descriptor would refuse an engine a product runs. Adapter first (the old switches and their tests stay until the registry's tests pass), and SL01's witness test is what keeps the descriptors honest.
- **Pruning removes versions a rollback wants** (SL07): the dry run, "never the served version" and the preselection (D27) keep it from doing so silently; plan 30's own screen will fold this one in.
- **Ad hoc state is a large surface** (SL25): a row cap, expiry and scope rules are part of the first version, and nothing else waits on it.
- **Columns checked at publish cost a query per table** (SL06): `WHERE 1 = 0` returns no rows and costs the planner, not a scan; the check runs once per publish, not per query.
