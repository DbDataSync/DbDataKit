# Plan 18: lineage, what is left

Status: **in progress** (audited 2026-11-12 against the code). What is built (the graph model, identity, queries, the commands, the Build, Sync and Runner graphs, the console's join and page) is in [docs/lineage.md](../lineage.md) and the READMEs of `DbDataKit.Lineage` and `DbDataKit.Lineage.Cli`. This plan holds the slices still open; the ids G06 to G12 are as in plan 19's lanes.

Re-audited 2026-11-12 against the code, row by row: **G08, G11b, G07b, G16 are done** (see the rows); **G10b, G06b and G12 are done in part** and say what is left in their rows (Build's own run overlay needs a tracking copy on a server to show; no job node per load, decided; the Store has no documents, extractions or promotions to emit); G17 was already built. The kit's `external-system` kind (plan 27a IX12) is built as a library only. G13 to G15 are "later, not scheduled" and untouched. The plan stays until the three partial rows are finished or dropped by the owner.

Formats: no slice changes a file in `docs/formats.json`. The lineage wire form (`LineageJson`) is not a stored file and has no registry entry; G10b adds a property to it (additive: the console reads it, a document of an unknown kind is still refused). The `lineage` state module (G07b) is state, versioned by `DbDataKit.State`'s own mechanism.

Editors: lineage is read by screens (the console's Lineage page), not authored, so G07b to G12 need no editor row. The one slice that lets a person author lineage, G13, has its row in [docs/ui-editors.md](../ui-editors.md).

1. **Manual entries are a file first** (G13), authored in git like other definitions, with the console form after. Default taken (owner delegated, 2026-11-09).
