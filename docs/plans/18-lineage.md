# Plan 18: lineage, what is left

Status: **in progress** (audited 2026-11-09 against the code). What is built (the graph model, identity, queries, the commands, the Build, Sync and Runner graphs, the console's join and page) is in [docs/lineage.md](../lineage.md) and the READMEs of `DbDataKit.Lineage` and `DbDataKit.Lineage.Cli`. This plan holds the slices still open; the ids G06 to G12 are as in plan 19's lanes.

Re-audited 2026-11-11: G10b and G17 are built (rows done), nothing else moved; G08, G11b, G07b, G06b, G12 and G16 are open as written. Audit, row by row, against the code: **G08** is open (`git grep -i lineage DbDataGateway/src` finds nothing: the Gateway has no graph and no `lineage` noun). **G11b**: the edge kinds `serves`, `extracts`, `promotes` and `reads` are defined in `EdgeKind` and no product emits one (only tests use `reads`); the `binds` half is built (`BuildLineage`). **G10b** (2026-11-11): the wire form and the page carry the newest run of each edge; no server sends one yet. **G07b**: Sync serves `GET /api/lineage` (`SyncLineage`, `SyncLineageRuns`), and `DbDataKit.Lineage.Cli` is mounted on Build's and the Runner's command lines but not Sync's; no server builds its graph in `LineageStore` (`git grep LineageStore` finds the library and its tests only). **G06b**: `LineageConformanceTests.After_a_refresh_each_load_edge_carries_its_last_run_from_the_tracking_tables` exists; whether it has run on the engines is not known from the repository. **G12**: neither DbDataStore nor the apps host emits anything. **Retention**: `LineageStore.PruneRuns` is called by nothing but its test. **Engine defaults** (G17): built, `LineageIdentity` reads the registry's `default_port`. Nothing in the old list was already built, and nothing is obsolete.

Formats: no slice changes a file in `docs/formats.json`. The lineage wire form (`LineageJson`) is not a stored file and has no registry entry; G10b adds a property to it (additive: the console reads it, a document of an unknown kind is still refused). The `lineage` state module (G07b) is state, versioned by `DbDataKit.State`'s own mechanism.

Editors: lineage is read by screens (the console's Lineage page), not authored, so G07b to G12 need no editor row. The one slice that lets a person author lineage, G13, has its row in [docs/ui-editors.md](../ui-editors.md).

## Decisions

1. **Manual entries are a file first** (G13), authored in git like other definitions, with the console form after. Default taken (owner delegated, 2026-11-09).
2. **The Gateway's lineage never holds per-query records** (unchanged: they belong to the activity log).
