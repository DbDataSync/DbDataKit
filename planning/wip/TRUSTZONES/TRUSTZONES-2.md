Not built: docs page, README lines, plan cleanup.

Default 1 (proposal): isolation is per schema in the one database, each login with its own registry (`<login>_registry.modules`); the console's one query over every service's runs, audit and notifications no longer finds the other services' modules in a shared registry. Example: an install on one PostgreSQL database, the Runner's login cannot read the Gateway's `dbdatakit_gateway_main_runs`; the console reads the Runner's runs through the Runner's API.
Default 2 (proposal): the `group` topology keeps the built-in names (one database per group is the boundary); only `install` writes per-login namespaces.
Question: the logins are created by the administrator (no password is ever printed or generated by the suite).
