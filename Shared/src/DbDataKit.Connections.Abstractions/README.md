# DbDataKit.Connections.Abstractions

Contracts (plan 06) for the shared connection definition, provider interfaces, credential policy and the failure model. No client libraries.

## Contract

- `ConnectionDefinition` (schema `connection/1`, and `connection/2` which adds the optional sections `cache` and `checks`, plan 24a UC03): `engine`, `dialect`, `access` (`readonly|readwrite`), `address` XOR `connection_string` XOR `connection_string_secret`, `auth`, `read_login`, `write_login`, `tls`, `timeouts`, `properties`, `extensions`.
  Keys are snake_case; `schema:` is required. Load with `ConnectionDefinitionLoader.Load(yaml)`: strict (unknown keys are errors with a suggestion), then semantic rules: address XOR string, no write login on a read-only connection, no plaintext credentials in a connection string, no credential/host/TLS keys in `properties`, valid secret references, complete logins. `ConnectionDefinitionLoader.JsonSchema()` generates the JSON Schema.
- **Kinds** (plan 27a IX01, `connection/2`, additive): `kind` is `database` (the default; a database file reads exactly as before), `http` (an API) or `model-provider`. An outside kind has an `endpoint` (an http or https address with no user name, password or query: a key is never part of it) and `sign_in`
  (`method` `none`, `api_key`, `basic`, `oauth2_client_credentials` or `client_certificate`, with the **reference** of each secret: `key_secret`, `password_secret`, `client_secret_secret`, `certificate_secret`; a secret written as itself is refused without being echoed). A model provider adds `model_provider:` (`provider`,
  `locality`, `purpose`, `auth_style`, `models` with window, largest answer and price per million tokens). A format-1 file cannot say a kind; a file of an unknown kind is refused naming the file (`DBD-CONN-013`); a program that keeps database connections only (Sync, Gateway, Build, which call `Load` as before) refuses an outside file naming it
  (`DBD-CONN-014`); the console and the runner read every kind with `Load(..., outsideKinds: true)` or `LoadFileOfAnyKind`. An outside file has none of the database keys (`engine`, `address`, `auth`, `cache`, ... `DBD-CONN-015`). A runner slot of an outside kind needs no change to `package/1`: a slot's `kind` is free text (`http`).
- `ConnectionFailure.IsTemporary` (IX01): network, timeout, `RateLimited` and `Unavailable` are temporary, everything else (login, TLS, permission, syntax, unsupported, `NotFound`, other) is permanent; a retry reads it and `TaskFailure.KindOf` maps it.
- `LoginRole` and `ConnectionDefinition.LoginFor`: **read never falls back to the write login**; write may fall back to `auth`.
- TLS defaults: encrypt on, verify on, `trust_server_certificate` off. Opting out is explicit, per connection, and reported as a warning by the loader; `ConnectionPolicy.AllowTlsOptOut=false` refuses it outright.
- Timeouts are never null (`connect_s` 15, `command_s` 300).
- `IDbProvider`, `IConnectionStringComposer`, `ConnectionContext`, `ResolvedLogin`, `ReadOnlySession` (recipe: connection-string keys, session statements, honest `ReadOnlyEnforcement` level), `ConnectionTestResult`.
- `ConnectionFailure { Kind, Code, Engine }`: `PublicMessage` is fixed text per kind, never driver text. `FailureClassifier` maps any exception through pluggable `IFailureMapper`s (engine packages), then SQLSTATE, then exception types. Raw text exists only when the classifier is built with `includeRaw: true`, and is passed through the Plan 02 redactor. `ConnectionFailureException` does not keep the inner exception.
- `CredentialPolicy`: the deny-list for `properties` (shares `CredentialKeyDetector` with Plan 02) and the integrated-security key list used by pass-through injection.

## Decisions

- Product settings live under `extensions.<product>` and are kept as YAML nodes (`ExtensionBag`), so each product binds its own part without the shared type knowing it.
- Plan 04's `ICatalogReader` does not exist yet, so `IDbProvider` has no `Catalog(...)` member; it is added when Plan 04 part B lands.
- `schema: connection/1` is checked by the loader before binding (Config's `schema: kind/int` form is not implemented), and bound with `VersionKey = "schema"`.

**Format 2, the serving data source (plan 24a UC03).** `schema: connection/2` is `connection/1` plus two optional sections, so a data source can carry its cache setting with the definition that is published and promoted. `cache:` has `enabled` (off unless `true`), `ttl` (`90s`, `5m`, `2h`; at most `24h`; default `5m`), `scope` (`caller`, `rules`, `shared`; default `caller`) and `dataset`; the values are checked with `CacheSection` of `DbDataKit.Config.Yaml`, and the cache cannot be turned on for a data source that names no server and no database (no `address` host or database and no `connection_string`: it has no lineage identity to expire entries by, `DBD-CONN-010`). `checks:` holds the data source's data quality checks, `check/1` entries read by `DbDataKit.Quality` (23a FQ01): each names the table it is about in `dataset` and gets the seven kinds' parameters, `severity` and `on_error`; a bad check is refused with the file and line, and `ConnectionDefinition.CheckDefinitions` has them. A `connection/1` file that has either section is refused with `DBD-CONN-009` naming the file and line and the fix `schema: connection/2`; a `connection/3` file is refused by its version (`DBD-110`). Files are written as `connection/1` until they use a section of format 2; `ConnectionDefinitionLoader.FormatOfText` is the format a published data source records. The generated JSON Schema (`JsonSchema()`) lists both sections.

**Grants (plan 22a GP03, owner decision of 2026-11-08).** `schema: connection/2` also has the optional section `grants:` that says who may read a serving data source: `groups` (home groups; names match ignoring case, none empty, padded or repeated) or `everyone: true`, never both. It is part of the definition a Build project publishes: the publish replaces the Gateway's copy completely, and the Gateway has no grants of its own. A data source with no `grants` is used by no home user. `ConnectionDefinition.Grants` has it; a `connection/1` file that has it is refused with `DBD-CONN-009` naming the file and line and the fix `schema: connection/2`; a bad list is `DBD-CONN-012`. The Gateway reads `grants` as it reads `extensions.gateway.groups` in a file made by hand (a file names one place, not both); Build's connection file authors it (`connections/<name>.yaml`) and its publish sends it.
