# DbDataKit.State.Cli

The shared `state` noun of every product's command line (plan 29b, M7). A product lists `StateVerbs.Create(new StateVerbContext(...))` with its other nouns and passes its program name, how to find its state from the command's options (`Locate`), its module list (or `null` when it has none yet) and its scope.

* `state show [--offline]`: engine, connection (secrets masked, references shown as written), where each module's tables are, each module's version in the registry against this binary, what is pending. Read-only: it opens no `StateDatabase`, so nothing is created or migrated; a missing SQLite file stays missing.
* `state test`: settings, connection, registry, rights (`StateRights`), engine version (`EngineSupport`), schema clash and refusals, pending migrations the login may not apply. Stops at the first failure with one sentence that names the fix. Exit codes (`StateExit`): 0 ok, 2 wrong use, 10 settings, 11 unreachable or no such database, 12 login refused, 13 registry unreadable, 14 rights missing, 15 engine too old, 16 schema clash, 17 pending migrations this login may not apply, 18 the service would refuse the database.
* `state grants --login <name> [--migrate]`: the `GRANT` statements of `StateGrants` for the product's layout.

* `state export --to <directory> [--include-secrets-check]`: writes the state to a snapshot (`StateSnapshotService.ExportAsync`), one progress line per table; `--include-secrets-check` searches every file of the snapshot (table files decompressed) for the resolved credentials of the connection string and removes the snapshot if one is there (exit 27).
* `state import --from <directory> [--migrate-after true|false]`: loads a snapshot into the empty state database the settings name; a failed import empties the target again; prints how to start the product afterwards.
* `state verify`: `--snapshot <dir>` checks the snapshot against its own manifest (no database, no settings), `--snapshot <dir> --db` (or `--against <snapshot dir>`) compares the current state with it, `--other-engine/--other-connection/--other-sqlite/--other-schema/--other-prefix` (or `--against <settings file>`, whose `state:` section names the other side) compares it with another database; the other connection holds secret references, never a written-out password. `--rehash-payloads` also hashes the payload bytes in the database. Exit 23 when anything differs, with the table and the first rows named.
* `state move --to-engine <e> [--to-connection <string with secret references>] [--to-schema <s>] [--to-prefix <p>] [--keep-snapshot] [--yes]`: `StateMoveService` (export, import into the empty target, verify against the snapshot and the source, then write the new `state:` section of the settings file, keeping the old file beside it). It prints the plan first and needs `--yes` or a typed yes (exit 26 otherwise); the old database is not touched; the restart instruction and the way back come from `MoveResult`. A product whose `StateTarget.SettingsFile` is null (it keeps no file with a `state:` section: the Proxy, the server of Store and Build) says so and points to export and import.

All four work offline: the product's service has to be stopped, and a live instance (or a SQLite file another process holds) refuses an export or a move with its name. Exit codes added by these verbs (`StateExit`, the range 20 to 29, the codes above are unchanged): 20 export refused (instance in use, file held, directory not empty), 21 target not empty, 22 snapshot unusable or a file unreadable, 23 a difference found, 24 the database is not ready to be read (empty, or older than this software: start the product once), 25 a move stopped at a step (settings unchanged), 26 move not confirmed, 27 a secret found in a snapshot. All print `--json` documents like `state show` where the host has them.

`StateVerbContext.ConfigureMove` is a test seam: it changes the `MoveOptions` of a move (for example `AfterImport`, to inject a failure after the import).

Verbs added later go in files of their own and are added to the list in `StateVerbs.Create`; the ones above do not change.
